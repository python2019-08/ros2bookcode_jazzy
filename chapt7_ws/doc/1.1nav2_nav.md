# ch02.问题：RViz2 报 TF / RobotModel 错误

现象见 [doc/error01_nav2_rviz2.png](error01_nav2_rviz2.png)：

- `Global Status: Error`
- `RobotModel` 下每个 link 都报 `No transform from [xxx]`（如 `base_footprint`、`base_link`、`laser_link`、`camera_link` 等），但 `URDF parsed OK`（1 messages received at 18.9 hz）
- Nav2 面板：`Navigation: inactive`，`Localization: active`
- 地图（map）能正常显示，但机器人模型不显示

## 根因

TF 树在 `map → odom → base_footprint` 这一段断了。

- URDF 本身没问题（RViz 已收到并解析 `robot_description`）。`nav2_default_view.rviz` 的 Fixed Frame 是 `map`，
  所以每个 link 都报 `No transform from [xxx] to [map]`，robot model 自然显示不出来。
- 地图能显示是因为 Map/Grid 的坐标系就是 Fixed Frame `map`，不需要机器人 TF。
- `Navigation: inactive` 很可能是连锁反应：`nav2_costmap_2d` 在 activate 阶段等不到 `map → base_link`
  的变换会直接激活失败（报错字符串：*"Failed to activate ... because transform ... did not become available
  before timeout"*），navigation 的 lifecycle manager 起不来，RViz 面板就显示 inactive。
  terminal 02 里应该能看到这条报错。

## 诊断命令（另开一个终端 03）

```sh
ch07WS=/home/abner/a2/zdev/nv/adas-01/ros/ros2bookcode_jazzy/chapt7_ws
cd ${ch07WS} && source install/setup.bash

ros2 control list_controllers
ros2 topic hz /odom
ros2 run tf2_ros tf2_echo odom base_footprint
ros2 run tf2_ros tf2_echo map odom
```

## 情况 A：`list_controllers` 里没有那两个控制器（最常见）

本工程在 `fishbot.urdf.xacro` 里把 `xacro:gazebo_control_plugin` 注释掉了，运动和 odom 全靠 ros2_control：

- `odom → base_footprint` 由 `fishbot_diff_drive_controller`（`enable_odom_tf: true`）发布；
- 控制器没起来 → 没有 `/odom`、没有 odom TF → AMCL 也处理不了激光 → 连 `map → odom` 都没有
  → 就是截图里的状态。

手动补加载：

```sh
ros2 control load_controller --set-state active fishbot_joint_state_broadcaster
ros2 control load_controller --set-state active fishbot_diff_drive_controller
```

加载成功后应能看到：

- `ros2 topic hz /odom` 约 50 Hz；
- `tf2_echo odom base_footprint` 持续有输出。

**为什么会漏加载**：`gazebo_sim.launch.py` 里 `ros2 control load_controller` 挂在 `spawn_entity_node`
的退出事件上，只执行一次、没有重试；而 controller_manager 是 gz_ros2_control 插件随模型一起加载才起来的，
这一步经常“抢跑”失败。

修复：改用 `TimerAction` 延时加载。

```python
from launch.actions import TimerAction

# 在 LaunchDescription 中替换原来的事件链
TimerAction(period=3.0, actions=[load_joint_state_controller]),
TimerAction(period=6.0, actions=[load_fishbot_diff_drive_controller]),
```

## 情况 B：控制器 active、`odom → base_footprint` 也有，但 `map → odom` 没有

说明 AMCL 还没有定位。`nav2_params.yaml` 里 amcl 没有设置 `set_initial_pose`，第一次必须在 RViz 里：

1. 点击 **2D Pose Estimate**；
2. 在地图上点击机器人的实际位置；
3. 按住拖出朝向箭头（朝向要对着激光/地图里的实际朝向）。

之后 AMCL 才会发布 `map → odom`，robot model 出现。

也可以在 `nav2_params.yaml` 的 `amcl:` 下写死初始位姿（要同时和 Gazebo 里的出生点、地图原点对得上）：

```yaml
    set_initial_pose: true
    initial_pose:
      x: 0.0
      y: 0.0
      z: 0.0
      yaw: 0.0
```

## 恢复顺序

costmap 一旦激活失败不会自动重试，所以 TF 修好后：

1. 直接在 Nav2 面板按 **Startup**；不行就 Ctrl-C 重开 terminal 02；
2. `ros2 lifecycle get /controller_server` 确认状态变成 `active`；
3. 若 terminal 02 还有别的 configure/activate 报错，把日志一并检查。

## 附：一处配置不一致（非本次报错原因）

`nav2_params.yaml` 中 costmap、`bt_navigator`、`behavior_server` 使用 `robot_base_frame: base_link`，
而 amcl 使用 `base_footprint`。两者由固定关节相连，功能上没问题，但排查 TF 时容易看花眼，建议统一。

# ch03.设置 `set_initial_pose`后，机器人在rviz2上显示正常了，但是设置 nav2 goal后，没有进行导航

## 现象

- `set_initial_pose: true` 后 TF 正常，robot model 能在 RViz 里显示；
- 在 RViz 里点 **Nav2 Goal** 下发目标点，小车不动，没有路径/控制输出。

## 根因（两层问题叠加）

### 1. Navigation 栈很可能根本没激活

Jazzy 的 `nav2_bringup/launch/navigation_launch.py` 比书里 Humble 版本多启动了几个节点，
并且把它们放进了 lifecycle manager 的 `node_names`：

```
controller_server, smoother_server, planner_server, route_server, behavior_server,
velocity_smoother, collision_monitor, bt_navigator, waypoint_follower, docking_server
```

原 `nav2_params.yaml` 里没有 `collision_monitor` 和 `docking_server` 两段参数。单独复现的结果：

- `collision_monitor`：`Error while getting parameters: parameter 'observation_sources' is not initialized` → configure 失败
- `docking_server`：`Charging dock plugins not given!` → configure 失败

任意一个节点 configure 失败，整个 navigation lifecycle manager 启动失败，`bt_navigator` 不会 active，
下发的 goal 就没人处理。terminal 02 里能搜到这两条报错。

### 2. 速度指令类型不匹配（Twist vs TwistStamped）

Jazzy 的速度链路：

```
controller_server → /cmd_vel_nav → velocity_smoother → /cmd_vel_smoothed
                  → collision_monitor → /cmd_vel → diff_drive_controller
```

- Jazzy 的 `velocity_smoother` / `collision_monitor` **默认发 `geometry_msgs/msg/Twist`**；
- Jazzy 的 `diff_drive_controller` **只订阅 `geometry_msgs/msg/TwistStamped`**
  （和建图时 teleop 必须加 `stamped:=true` 是同一个原因）。

类型不匹配时消息不会投递，所以会出现“路径规划有了、但轮子不动”。

实测：默认参数下 velocity_smoother 的 `/cmd_vel_smoothed` 是 `Twist`；
加 `enable_stamped_cmd_vel: true` 后，输入输出都变成 `TwistStamped`。

## 已做的修改（`src/fishbot_navigation2/config/nav2_params.yaml`）

- `controller_server`、`behavior_server`、`velocity_smoother` 增加 `enable_stamped_cmd_vel: true`
- 新增 `collision_monitor` 段：
  - `enable_stamped_cmd_vel: true`
  - `cmd_vel_in_topic: cmd_vel_smoothed`、`cmd_vel_out_topic: cmd_vel`
  - `observation_sources: ["scan"]`
  - `FootprintApproach` 先设 `enabled: False`（避免刚调通就被限速/停车，确认能跑后再打开）
- 新增 `docking_server` 段（提供 `dock_plugins`，让 configure 能通过）

已验证：

- collision_monitor 用这套参数能 configure + activate，`/cmd_vel` 类型为 `TwistStamped`；
- docking_server 用这套参数 configure 成功；
- `bt_navigator` 的 `plugin_lib_names` 里的 BT 库在 Jazzy 全部存在。

## 验证步骤

params 只在启动时读取，先重启 terminal 02，然后：

```sh
ros2 lifecycle get /controller_server     # 期望 active [3]
ros2 lifecycle get /collision_monitor     # 期望 active [3]
ros2 lifecycle get /docking_server        # 期望 active [3]

ros2 topic info -v /cmd_vel
# 期望：Type: geometry_msgs/msg/TwistStamped
#       publisher   = collision_monitor
#       subscriber  = fishbot_diff_drive_controller

ros2 topic echo /cmd_vel                  # 发 goal 后应有持续输出
```

## 若仍不动，继续查

1. `Navigation` 仍为 inactive：看 terminal 02 第一个报错的节点名，通常是缺少该节点的 params 段；
2. `/cmd_vel` 有数据但车不动：
   - `ros2 control list_controllers` 确认两个控制器是 `active`；
   - `ros2 topic hz /odom` 确认 odom 在发布；
   - controller 的 `cmd_vel_timeout: 0.5` 和 `use_sim_time` 是否一致。

# ch04.重启后仍不导航：Humble 旧参数在 Jazzy 上导致 configure FATAL

## 现象

terminal 01 里控制器正常 active，但每秒刷：

```
[fishbot_diff_drive_controller]: Velocity command timed out. Braking.
```

RViz 里 Navigation 仍是 inactive，下发 goal 没反应。

查询各节点生命周期状态：

```sh
ros2 lifecycle get /controller_server    # inactive [2]
ros2 lifecycle get /planner_server       # unconfigured [1]
ros2 lifecycle get /bt_navigator         # unconfigured [1]
ros2 lifecycle get /collision_monitor    # unconfigured [1]
```

`smoother_server`、`controller_server` 停在 `inactive`，其余全是 `unconfigured` ——
说明 lifecycle manager 在 configure 中途失败并中止了，而不是速度类型的问题。

> `Velocity command timed out. Braking.` 只是“没有收到 `/cmd_vel`”的结果，
> 因为 nav2 根本没起来，不是控制器的问题。

## 根因

nav2 的日志不在 terminal 02 里（composable 节点被装进 `nav2_container`），要到
`~/.ros/log/` 下找容器日志：

```sh
ls -td ~/.ros/log/*/ | head -1
grep -aE "FATAL|ERROR" ~/.ros/log/component_container_isolated_*.log | grep -v amcl | head
```

里面第一条真正的错误是：

```
[FATAL] [planner_server]: Failed to create global planner. Exception:
According to the loaded plugin descriptions the class nav2_navfn_planner/NavfnPlanner
with base class type nav2_core::GlobalPlanner does not exist.
Declared types are  nav2_navfn_planner::NavfnPlanner ...
[ERROR] [lifecycle_manager_navigation]: Failed to change state for node: planner_server
[ERROR] [lifecycle_manager_navigation]: Failed to bring up all requested nodes. Aborting bringup.
```

书里的参数是 Humble 时代写的，插件类名用 **斜杠** `pkg/Class`；Jazzy 只认
**双冒号** `pkg::Class`。`planner_server` configure 直接抛异常，整个 navigation
lifecycle 就此中止，后面的 `bt_navigator`、`velocity_smoother`、`collision_monitor`
等统统停在 `unconfigured`，所以 ch03 里加的 `enable_stamped_cmd_vel` 一直没机会生效。

单独用 `--params-file` 跑各节点 configure，又发现第二处：

```
[FATAL] [bt_navigator]: Failed to create navigator id navigate_to_pose.
Exception: ID [ComputePathToPose] already registered
```

原因：Jazzy 的 `bt_navigator` 会自动注册内置 BT 插件，旧参数里的
`plugin_lib_names` 又把同一批库加载一遍，重复注册直接 FATAL。

## 修改内容（`src/fishbot_navigation2/config/nav2_params.yaml`）

1. 插件类名全部改成 `::`：
   - `nav2_navfn_planner/NavfnPlanner` → `nav2_navfn_planner::NavfnPlanner`
   - `nav2_behaviors/Spin|BackUp|DriveOnHeading|Wait|AssistedTeleop`
     → `nav2_behaviors::Spin|BackUp|DriveOnHeading|Wait|AssistedTeleop`
2. 删除 `bt_navigator.plugin_lib_names` 整段（Jazzy 自动注册内置 BT 插件）。
3. amcl 增加固定初始位姿，省掉每次重启后点 `2D Pose Estimate`：

   ```yaml
   set_initial_pose: true
   initial_pose:
     x: 0.0
     y: 0.0
     z: 0.0
     yaw: 0.0
   ```

## 验证

用隔离的 `ROS_DOMAIN_ID` 逐个节点 configure，确认全部通过：

```sh
export ROS_DOMAIN_ID=88
P=src/fishbot_navigation2/config/nav2_params.yaml
ros2 run nav2_planner planner_server --ros-args --params-file $P &
ros2 lifecycle set /planner_server configure
ros2 lifecycle get /planner_server      # inactive [2]

ros2 run nav2_bt_navigator bt_navigator --ros-args --params-file $P &
ros2 lifecycle set /bt_navigator configure
ros2 lifecycle get /bt_navigator        # inactive [2]

ros2 run nav2_velocity_smoother velocity_smoother --ros-args --params-file $P &
ros2 lifecycle set /velocity_smoother configure
ros2 lifecycle set /velocity_smoother activate
ros2 topic info /cmd_vel_smoothed       # geometry_msgs/msg/TwistStamped
```

> 注意：`ros2 run` 的子进程在 kill 父进程后可能残留，测完用 `pgrep -af <name>` 清理。

## 重新启动后的检查清单

1. Ctrl-C terminal 02（terminal 01 的仿真不用动），重新执行
   `ros2 launch fishbot_navigation2 navigation2.launch.py`；
2. 十个节点都应为 `active [3]`：

   ```sh
   for n in controller_server smoother_server planner_server route_server \
            behavior_server velocity_smoother collision_monitor bt_navigator \
            waypoint_follower docking_server; do
     printf "%-20s " $n; ros2 lifecycle get /$n

   ```

3. `ros2 topic info /cmd_vel`：类型 `TwistStamped`，subscriber 是
   `fishbot_diff_drive_controller`；
4. 发 goal 后 `ros2 topic echo /cmd_vel` 应有持续输出，terminal 01 不再刷
   `Velocity command timed out`。
